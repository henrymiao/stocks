# 术语表

这套框架的输出用英文字段名，数字也不自带上下文。这份表把每个术语定义一次，以后直接引用。

## 最容易混的一组：三个"结论"字段

输出里有三个看起来都像结论的字段，**回答的是完全不同的问题**：

| 字段 | 回答什么 | 什么时候看 |
|---|---|---|
| `label` | 你**已经持有**的这笔，现在怎么看 | 有持仓时 |
| `position_decision` | 你**已经持有**的这笔，该做什么动作 | 有持仓时 |
| `entry_decision` | 能不能**新建仓或加仓** | 考虑买入时 |

**`entry_decision=reject` 不是叫你卖出**，它只是说"现在不该买入"。已有仓位看前两个字段。

## `entry_decision` 的四个取值

| 值 | 含义 | 仓位 |
|---|---|---|
| `enter` | 全部门通过，证据完整 | 风险测算的完整仓位 |
| `probe` | 证据只够一次**小额试探** | 打折 + 硬上限（short ×0.25 封顶5% / swing ×0.20 封顶5% / core ×0.30 封顶8% / 杠杆 ×0.20 封顶3%） |
| `watch` | 有**证据缺失**，等数据补齐 | — |
| `reject` | 有**硬门失守**或被方法层限制 | — |

反直觉的一点：**缺失比失守宽容**。判定阶梯里"有缺失→watch"排在"有失守→reject"前面。所以失守 7 道门的可能是 `watch`，失守 4 道的可能是 `reject`。

## `label` 的六个取值

`strong-watch` 重点观察｜`low-buy-zone` 低吸区｜`hold` 继续持有｜`trim-on-strength` 强势时可减｜`risk-reduce` 降低风险｜`avoid` 回避

## `setup_score`

0–100 的综合分，算法是 **四个证据簇 × 轨道权重**。

| 证据簇 | 内容 |
|---|---|
| `thesis` 论点 | 基本面、估值、业务质量 |
| `market_behavior` 价格行为 | 趋势、相对强度、资金流（三者归一后**只算一次**，防止同一条价格序列被重复计数） |
| `environment` 宏观背景 | 市场机制、宏观风险、跨市场 |
| `risk_fit` 风险适配 | 仓位与止损结构是否成立 |

**同一只股票在不同轨道分数不同**，因为权重不同——不是数据变了。

## 轨道（horizon）

| | `short` | `swing` | `core` |
|---|---|---|---|
| 打算持有 | 1–3 天 | 1–4 周 | 多季度 |
| 时间止损 | 2 场 | 5 场 | **120 场（≈半年）** |
| `thesis` 权重 | 0.20 | 0.30 | **0.50** |
| `market_behavior` 权重 | **0.40** | 0.35 | 0.15 |
| probe 门槛 | 58 | 62 | 55 |

**短线主要看价格怎么走，核心主要看你为什么持有它。** 用错轨道是范畴错误：拿多季度的持仓去跑 swing，会被一到四周的择时规则否决掉每一次加仓。

### 两个叠加层（overlay）

- **`leveraged-overlay-v1`**：杠杆 ETF。仓位上限降到 15%，目标和移动止损收紧，且**强制要求确认标的**。
- **`defensive-overlay-v1`**：低波动价值/防御股。**去掉相对强度和量能确认两道门**——一只每天波动 0.2% 的银行股跑不赢半导体定义的基准，那是它的属性不是缺陷。权重从价格行为移 0.15 到论点。**趋势、入场触发、阻力空间等"这笔交易成不成立"的门全部保留。**

## 门（gate）

14 道硬性检查，每道结果是 通过 / 失守 / 缺失。

`data-confidence` 数据可信度｜`structured-exit-plan` 退出计划完整｜`session-ready` 交易时段就绪｜`trend-regime` 趋势方向｜`relative-strength` 相对强度｜`volume-confirmation` 量能确认｜`entry-trigger` 入场触发｜`resistance-room` 阻力空间｜`market-regime` 市场机制｜`liquidity` 流动性｜`portfolio-heat` 组合风险额度｜`independent-clusters` 独立证据数｜`weekly-alignment` 周线对齐｜`event-window` 事件窗口

**`resistance-room` 是唯一由价格决定的门**，所以也是唯一能靠"等更低的价格"解决的。其余门价格解决不了——`entry_zone.py` 会把它们单独列出来，只要还有一道没过，`actionable` 就是 False。

## R

**1R = 入场价到止损的距离。** 所有目标都用 R 表示，所以不同标的可以横向比较：赚 2R 就是赚了两倍的单笔风险，与股价高低无关。

## 组合热度（portfolio heat / open risk）

**持仓权重 × 到止损的跌幅**，对 **NAV（含现金）** 计算。上限：组合 6%、单主题 3%。

关键：**它只影响"能建多大仓"，不影响任何分析结论**。setup 分数、证据簇、其他 13 道门都与它无关。做纯标的比较时可以不传 `--portfolio`。

注意两件事：
- **分母必须含现金**。用股票市值当分母会系统性放大每个集中度数字。
- **浮盈会推高热度**。价格涨而止损不动，到止损的距离就变大——所以盈利仓位需要定期按新的结构位上移止损。

## 方法层限制（method restrictions）

一个只能**降级、不能升级**的旁路。正面证据永远不加分；负面证据可以把结论往下压。

常见的：`swing-stage-3`/`stage-4`（趋势末段/派发期，禁止新增摆动风险）｜`thesis-invalidated`｜`source-conflict`｜`decline-structural-impairment`（结构性受损，**任何价格都不是低位**）｜`decline-cause-unconfirmed`｜`decline-bear-case-unbounded`。

## 下跌原因分类（decline）

在把价格当成"见底"的证据之前，先给下跌归类。**同样的 −30%，五种原因的"低位"含义互相矛盾**：

| 原因 | 有没有低位 |
|---|---|
| `liquidity` 流动性冲击 | 有，恢复最快 |
| `bounded-event` 有界的一次性事件 | 有，损失可估即可定价 |
| `valuation-reset` 估值重置 | 半有，新均衡要重算 |
| `structural-impairment` 结构性受损 | **没有，任何价格都不是** |
| `unconfirmed` 原因未确认 | 不能建仓，只能观察或封顶试探 |

**跌幅不是安全边际，盈利能力才是。**

## 怎么读输出

用 `--explain`（或 `cli explain --input <文件>`）把任何一份分析翻译成中文。摘要里的「盯这几个数就够」是把 30 个字段压成 3–5 个实际要看的。
